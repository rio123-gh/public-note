# OWL (Web Ontology Language)

オントロジーの文脈で登場するOWL（Web Ontology Language）は、一言で言えば**「データに『厳密な意味』と『論理ルール』を持たせ、コンピュータに高度な自動推論をさせるためのWeb標準言語（W3C標準）」**です。

単にデータをリンクさせるだけでなく、「この概念とこの概念は絶対に交わらない」「Aという関係が成り立つなら、逆のBという関係も自動的に成り立つ」といった、人間が頭の中で行っているロジックをデータそのものに埋め込むことができます。

まずは、セマンティックウェブやナレッジグラフの技術スタックにおけるOWLの位置づけから見ていきましょう。


## 1. RDF / RDFS / OWL の位置づけと違い

OWLを理解する最大の近道は、先行技術であるRDFやRDFSとの階層関係（表現力の差）を押さえることです。

データの抽象度や表現力が高まるにつれて、技術スタックのレイヤーが上がっていきます。

### RDF / RDFS / OWL の位置づけと違い

```text
+------------------------------------------+
|          Trust / Proof / Crypto          |
+------------------------------------------+
                     |
+------------------------------------------+
|              Logic / Rules               |
+------------------------------------------+
                     |
+------------------------------------------+
|                   OWL                    | [Advanced reasoning]
|            (Ontology Layer)              |
+------------------------------------------+
                     |
+------------------------------------------+
|                  RDFS                    | [Basic structure]
|           (Vocabulary Layer)             |
+------------------------------------------+
                     |
+------------------------------------------+
|                   RDF                    | [Raw facts]
|               (Data Layer)               |
+------------------------------------------+
                     |
+------------------------------------------+
|                Raw Data:                 | [Messy reality]
|       SQL, CSV, JSON, XML, Excel,        |
|               unstructured               |
+------------------------------------------+
```


| レイヤー | 役割 | できることの例 |
| :--- | :--- | :--- |
| **OWL**<br>(Ontology Layer) | 厳密な論理・ルールの定義 | 高度な推論のための制約条件を追加する。<br>・「温度センサー」と「振動センサー」は**互いに排他的（Disjoint）**である。<br>・「設置されている」という関係は**転移性（Transitive）**を持つ。 |
| **RDFS**<br>(Vocabulary Layer) | 基本構造（スキーマ）の定義 | クラスやプロパティの階層を作る。<br>・「温度センサー」は「計測機器」のサブクラス（子概念）である。 |
| **RDF**<br>(Data Layer) | 事実の記述 | 「主語・述語・目的語」のトリプルでデータを繋ぐ。<br>・「センサーA」は「温度センサー」である。<br>・「センサーA」は「工場X」に「設置されている」。 |

RDF/RDFSだけでは、「異常値を出しているセンサーが設置されているラインは、自動的に『要チェック状態』にする」といった複雑なロジックや制約を厳密に表現できません。それを可能にするのがOWLです。



## 2. OWLを構成する3つのコア要素

OWLの世界は、大きく次の3つの要素でモデル化されます。

- **Individuals（個体 / インスタンス）**
  現実世界の具体的なオブジェクトやデータそのものです。
  - *例:* `Sensor_A_101`、`Factory_Tokyo`
- **Classes（クラス / 概念）**
  共通の特性を持つ個体の「集合」です。
  - *例:* `TemperatureSensor`（温度クラス）、`CriticalAlert`（緊急アラートクラス）
- **Properties（プロパティ / 属性・関係性）**
  個体同士、または個体と値を結びつけるリンクです。プロパティには以下の2種類があります。
  - **Object Property:** 個体と個体を結ぶ関係（*例:* `isLocatedIn` [〜に設置されている]）
  - **Data Property:** 個体と具体的なデータ値（文字列や数値）を結ぶ関係（*例:* `hasThresholdValue` [閾値は80.0]）



## 3. OWLの真骨頂：「表現力」と「推論（Reasoning）」

OWLがただのデータベーススキーマと決定的に違うのは、**「リーゾナー（Reasoner：推論エンジン）」**を通すことで、明示的に書かれていない新しい事実をロジックから自動的に導き出せる（推論できる）点です。

これを可能にする、OWL特有の強力な表現力をいくつか紹介します。

### プロパティの特性（Property Characteristics）
関係性の「性質」を定義することで、データの自動補完が行われます。

- **転移性 (Transitive Property)**
  「部品Aは装置Bの一部」「装置BはラインCの一部」と定義すると、リーゾナーが自動的に「部品AはラインCの一部」と推論します。
- **対称性 (Symmetric Property)**
  「部屋Aは部屋Bに『隣接している』」とだけ書けば、逆向きの「部屋Bは部屋Aに『隣接している』」をわざわざデータとして登録しなくても自動で補完されます。
- **逆関係 (Inverse Of)**
  `hasPart`（〜を持つ）の逆は `isPartOf`（〜の一部である）と定義しておけば、片方を書くだけで双方向のリンクが完成します。

### クラスの論理演算と制約
クラス同士の関係を数学の集合論のように定義できます。

- **排他性 (Disjoint Classes)**
  「`NormalStatus` と `ErrorStatus` は排他である」と定義しておくと、もしある個体が両方に属してしまった場合に「このデータモデルは論理的に矛盾している」とエラー（インコンシステント）を検知してくれます。
- **等価性 (Equivalent Class)**
  「『温度が100度以上』かつ『プレッシャーが異常』な個体」という条件を満たすものを `DangerState` クラスと等価である、と定義します。すると、条件に合致したインスタンスが自動的に `DangerState` クラスに分類されます。


## 4. 現代のAI・LLM文脈におけるOWLの意義
- 近年、OWLをはじめとするオントロジー技術が再び注目されています。その理由は**「GraphRAG」**や**「セマンティックレイヤー」**の構築にあります。
- ナレッジグラフをLLMの外部知識として使う際、単にテキストをエンティティで繋いだだけのグラフだと、LLMが関係性の意味を誤解したり、文脈を正しく辿れなかったりします。
- ここにOWLで定義した「厳密なスキーマ（オントロジー）」を被せることで、データの一貫性が保たれ、LLMに対して**「このデータ構造における『一部』とは、どういう論理的意味を持つのか」**を正確にプロンプトやコンテキストとして渡すことが可能になります。



## 5. RDFSとOWLの決定的な違い

「クラスやプロパティを定義するなら、OWLと何が違うの？」と思われるかもしれません。一言で言えば**「表現できる論理の厳密さと複雑さ」**が違います。

RDFSは、あくまで「シンプルなツリー構造（階層）と、プロパティの適用範囲」を決めることしかできません。

| やりたいこと | RDFS | OWL |
| :--- | :---: | :---: |
| 「AはBのサブクラス（子概念）」と定義する | ✓ 可能 | ✓ 可能 |
| 「プロパティXの主語はクラスYである」と指定する | ✓ 可能 | ✓ 可能 |
| 「クラスAとクラスBは絶対に重複しない（排他）」と定義する | ✗ 不可能 | ✓ 可能 (`owl:disjointWith`) |
| 「関係Xは、逆向きの関係Yと同じ意味」と定義する | ✗ 不可能 | ✓ 可能 (`owl:inverseOf`) |
| 「条件Aと条件Bを両方満たすものをクラスCとする」 | ✗ 不可能 | ✓ 可能 (`owl:intersectionOf`) |

### 分かりやすい例
RDFSでは「既婚者」と「未婚者」というクラスを作ることはできます。しかし、「ある人が両方に同時に属してしまったらエラーにする（排他）」というルールはOWLを使わないと書けません。RDFSの段階では、データの矛盾をチェックするような高度な論理演算はできないのです。

---

### まとめ

- **RDF**：具体的な「事実（トリプル）」を書く。
- **RDFS**：事実を分類するための「クラスの親子関係（タクソノミー）」や「プロパティの枠組み」を決める。
- **OWL**：RDFSの上に、さらに「排他」「等価」「逆関係」などの高度な「数学的・論理的な制約」を追加する。
