## ■spaCyとGiNZAを使ってみる

### 体系

- **`spaCy`** と **`GiNZA`** の関係はこれまでと同じです。`spaCy`が基盤となる汎用フレームワークで、`GiNZA`はその`spaCy`を日本語に特化させた拡張ライブラリです。
- `GiNZA`は土台となる`spaCy`の機能を使って日本語を処理しますが、その際に「どのような知識（モデル）」を使うかによって、解析の速度や精度が変わるという関係性になります。プロジェクトの要件（速度が重要か、精度が重要かなど）に応じて、適切なモデルを選択することになります。

```python
自然言語処理 (NLP) の世界
└── spaCy (多言語対応の汎用NLPフレームワーク)
    ├── 基本的なNLP機能 (トークン化、品詞、係り受けなど)
    ├── 多様な言語モデル (例: 英語、ドイツ語)
    └── 拡張性・柔軟なパイプライン

        └── GiNZA (spaCyの日本語特化拡張ライブラリ)
            ├── 日本語形態素解析 (SudachiPy連携)
            ├── 日本語係り受け解析
            ├── 日本語固有表現抽出
            ├── 文節抽出 (GiNZA独自の機能)
            └── 内部処理の日本語最適化

                └── GiNZAで利用可能な日本語学習済みモデル群
                    ├── ja_ginza (標準モデル：速度重視)
                    │   └── 日本語の単語辞書、基本的な文法パターン
                    └── ja_ginza_electra (高精度モデル：精度重視)
                        └── Transformerベースの高度な学習済みモデル
                            └── より複雑な文脈や表現に対応

```

### spaCyとGiNZAとは

- **GiNZA**
    - 株式会社リクルートのAI研究機関「Megagon Labs」が中心となって開発し、国立国語研究所も貢献しています。
    - 開発リーダーは松田寛氏（Megagon Labs）。
- **spaCy**
    - Explosion社（アメリカ）が開発・提供する多言語対応の自然言語処理ライブラリです。
    - GiNZAはspaCyをベースに日本語解析機能を強化したプロダクトです。
- なぜ一緒に使うのか
    - GiNZAはspaCyのフレームワークを利用して日本語解析モデルを提供しています。spaCy自体は多言語対応の自然言語処理ライブラリですが、2019年までは日本語モデルが十分ではありませんでした。
    - そこでMegagon Labsと国立国語研究所がspaCyの上に日本語解析モデル（GiNZA）を構築し、spaCyの使い勝手とGiNZAの日本語解析能力を組み合わせることで、誰でも簡単に高精度な日本語解析ができるようになりました。

- 役割の違い
    - GiNZAはspaCyの「日本語版強化パック」のような位置づけで、spaCyのAPIやパイプラインをそのまま利用しつつ、日本語特有の解析に対応します

| **ライブラリ** | **主な役割・特徴** | **日本語対応** | **備考** |
| --- | --- | --- | --- |
| spaCy | 多言語対応の自然言語処理フレームワーク。構文解析や固有表現抽出など | △（デフォルトでは弱い） | GiNZAなしでも英語など多言語で利用可 |
| GiNZA | spaCyをベースに日本語に特化した解析モデルや辞書を追加。形態素解析や固有表現抽出を強化 | ○ | spaCyの上で動作し、日本語解析を強化 |

### GiNZAについて

- まず前提として、Ginzaは道具箱で、ja_ginzaはその道具箱に入っている特定の道具(モデル)という関係
- **GiNZA (ギンザ)**:
GiNZAは、Pythonで利用できる**オープンソースの日本語自然言語処理（NLP）ライブラリ**そのものです。強力なNLPライブラリであるspaCyをフレームワークとしており、日本語に特化した様々な解析機能を提供します。
GiNZA自体は、解析のための基盤やAPIを提供し、例えば文節抽出などのGiNZA独自の機能を利用できます。
- **`ja_ginza`**:
`ja_ginza`は、GiNZAで利用するための**事前学習済みの日本語モデル**の一つです。GiNZAが提供する解析機能を実際に利用するためには、このモデルをロードする必要があります。
`ja_ginza`は、**速度を重視した標準的なモデル**として提供されています。より高度な解析精度を求める場合は、`ja_ginza_electra`や`ja_ginza_bert_large`といった別のモデルも選択できます。これらのモデルは、Transformerベースの深層学習モデルを活用しており、解析精度が高い反面、メモリ消費量が多く、処理時間も長くなる傾向があります。
- **まとめると：**
    - **GiNZA**：日本語NLPの**ライブラリ本体**。機能を提供。
    - **`ja_ginza`**：GiNZAで利用する**事前学習済みの日本語モデル**の一つ。速度重視。
    - プログラムでGiNZAを使う際には、まず`pip install ginza`でライブラリ本体をインストールし、次に`pip install ja_ginza`（または他のモデル）でモデルをインストールします。そして、コード内で`spacy.load('ja_ginza')`のようにモデルをロードして使用します。
    - つまり、GiNZAは道具箱、`ja_ginza`はその道具箱に入っている特定の道具（モデル）という関係です。

### GiNZAのモデルについて

- `ginza`: GiNZA本体（spaCy拡張）
- `ja_ginza`: GiNZAの**実行速度重視モデル**
- `ja_ginza_electra`: より**精度重視の大きなモデル。**Transformerという深層学習技術をベースにした、より**高精度なモデル**です。より複雑な文章や微妙なニュアンスの解析に優れていますが、その分、処理速度は遅くなり、メモリ消費も多くなる傾向があります。

- 二つのインストール方法がある

|  | 説明 | 特徴 |

### 使い方

- 基本的な使い方

```python
text = "山田太郎さんのメールは yamada.taro@example.com です。住所は東京都新宿区西新宿2-8-1。"

# GiNZAによる匿名化（人名・地名）
nlp = spacy.load("ja_ginza_electra")

doc = nlp(text)
new_text = text

print(f"\n--- Processing: {text[:50]}... ---")
if not doc.ents:
    print("  -> No entities found.")
else:
    for ent in doc.ents:
        print(
            f"  -> Detected: '{ent.text}' (Label: {ent.label_}, Start: {ent.start_char}, End: {ent.end_char})"
        )

# reversedで後ろから置換（位置ズレ防止）
for ent in reversed(doc.ents):
    # ここを修正：デバッグ出力で確認できたラベル名に合わせる
    if ent.label_ in [
        "Person",
        "Postal_Address",
    ]:  # ラベル名を "Person" と "Postal_Address" に変更
        print(f"  -> Anonymizing: '{ent.text}' (Label: {ent.label_})")
        # 匿名化後の置換文字列も、検出されたラベル名を使用するように変更
        new_text = (
            new_text[: ent.start_char] + f"[{ent.label_}]" + new_text[ent.end_char :]
        )
```

- docの構造
    - textはdoc=nlp(text)によって、docオブジェクトに変換される
    - `doc` オブジェクトは反復可能で、各要素がテキスト内の**トークン**を表します。各トークンは `spacy.tokens.Token` オブジェクトであり、多くの属性を持っています。

```python
token = doc[0]

token.text: トークンの元のテキスト ("山田太郎")
token.lemma_: トークンの基本形/原形 (活用語の活用前の形など)
token.pos_: 品詞 ("NOUN", "VERB" など)
token.dep_: 依存関係ラベル (文法的な関係)
token.ent_type_: 所属する固有表現のラベル (例: "Person")
token.is_alpha: アルファベットかどうか
token.is_punct: 句読点かどうか
token.is_space: スペースかどうか
token.i: トークンのインデックス（0から始まる）
token.idx: テキスト内の開始オフセット（文字数）
```

## ■注意点

- 匿名化しても**再識別可能性（Re-identification Risk）**に注意する必要があります。
- GDPRや個人情報保護法に準拠する設計が求められます。
