# RDF（Resource Description Framework）

## RDFの概要

**RDF（Resource Description Framework：リソース記述フレームワーク）**は、ウェブ上にある「モノ」や「コト」の情報を、コンピュータが解釈・処理しやすい形で表現するための世界標準（W3C勧告）のデータモデルです。

主に、データを網の目のようにつなぐ「ナレッジグラフ（Knowledge Graph）」や「セマンティックウェブ」の基盤技術として広く活用されています。


## RDFの特徴

### 1. 最大の特徴：「トリプル」による表現

RDFでは、どんなに複雑な情報であっても、すべて**「主語（Subject）」「述語（Predicate）」「目的語（Object）」**という3つの要素の組み合わせ（これを**トリプル**と呼びます）に分解して表現します。

上記のシステム概念図（例）をトリプルに分解すると、次のような構造になります。

- **主語 (Subject)**: 記述の対象となるリソース（例：人物ノード `Bess Schrader`）
- **述語 (Predicate)**: 主語と目的語の関係性や属性（例：`employed by` / 〜に雇用されている）
- **目的語 (Object)**: 関係の宛先や具体的な値（例：組織ノード `Enterprise Knowledge`）

このトリプルを大量に積み重ねていくことで、データ同士が数珠つなぎになり、巨大な**グラフ構造（ネットワーク状のデータ）**が形成されます。

### 2. グローバルで衝突しない「URI」の利用

RDFでは、主語や述語に**URI（Uniform Resource Identifier）**というWebのURLに似た識別子を割り当てます。

これにより、世界中の異なるシステムが作成したデータであっても、名前の衝突（同姓同名の混同など）を起こさずに、データを安全に結合・リンクさせることができます。

### 3. 主要な記述形式（シリアライズ）

RDFモデルを実際にファイルに書き出したり、プログラム間でやり取りしたりするための構文（フォーマット）には、いくつかの種類があります。

| 形式名 | 特徴 | 主なユースケース |
| :--- | :--- | :--- |
| **Turtle** (タートル) | 人間にとって最も読みやすく、書きやすいシンプルなテキスト形式。 | ナレッジグラフの手動記述や設計・学習時 |
| **JSON-LD** | Webで標準的なJSONをベースに、RDFの概念を拡張した形式。 | Webサイトの構造化データ（SEO対策・Googleの検索エンジン最適化） |
| **RDF/XML** | XMLベースの初期からある形式。機械処理には向くが人間には冗長。 | レガシーなシステムや一部の標準化データとの連携 |



## RDFがもたらすメリット

- **柔軟なデータ統合**
  - 関係型データベース（RDB）のように、事前にガチガチのテーブル設計（スキーマ）を決めなくても、後から新しいトリプル（関係性）を自由に追加・結合できます。
- **機械による「推論」の実現**
  - 「AはBの親」「BはCの親」というデータがあれば、システムが自動的に「AはCの祖父母である」と判断するような、論理的なデータ補完（推論）が容易になります。


## RDFS(RDF Schema)
### RDFSの概要
- 一言で言えば「RDFで書かれたデータに、クラス（概念）やプロパティ（関係性）の『階層構造（分類）』を与えるための基礎的なスキーマ言語」
- RDFは「主語・述語・目的語」のトリプルで事実を記述する。しかし、RDF単体では「何がクラス（概念）で、何がインスタンス（具体的なモノ）か」「どの概念がどの子概念にあたるのか」というメタ的なルールを定義できません。
- それを補い、データ全体の「語彙（ボキャブラリー）」や「分類体系」を作るのがRDFSの役割です。

### RDFSが解決する課題（なぜ必要なのか）
- 例えば、RDFだけで次のようなデータを記述したとします。
  - [センサーA] [は、次のクラスに属する] [温度センサー]
  - [センサーB] [は、次のクラスに属する] [振動センサー]

- 人間が見れば「温度センサーも振動センサーも、どちらも『計測機器』の一種だな」と分かりますが、コンピュータにとっては単に独立した別々の文字列（リソース）でしかありません。
- ここにRDFSを導入することで、「『温度センサー』と『振動センサー』は、どちらも『計測機器』のサブクラスである」という共通の分類（スキーマ）を定義できるようになります。

### RDFSの最重要キーワード

RDFSは、主に以下の語彙（プロパティやクラス）を使ってデータ構造を定義します。これらはセマンティックウェブの世界で標準化されているため、世界中のシステムが同じ意味として解釈できます。

#### 1. クラス（概念）の階層を作るための語彙

- **`rdfs:Class`**
  - **概要**: すべての「クラス（概念）」の元となるクラスです。
- **`rdfs:subClassOf`**（〜のサブクラスである）
  - **概要**: クラス同士の親子関係（継承関係）を定義します。
  - **例**: `温度センサー` `rdfs:subClassOf` `計測機器`
  - **効果**: システムは「センサーAは温度センサーである」というデータから、「センサーAは（親クラスである）計測機器でもある」と自動的に推論（理解）できます。

#### 2. プロパティ（関係性や属性）のルールを作るための語彙

RDFでは関係性や属性のことを「プロパティ」と呼びます。RDFSを使うと、「そのプロパティがどのクラス同士を結びつけるか」という制約を定義できます。

- **`rdfs:subPropertyOf`**（〜のサブプロパティである）
  - **概要**: プロパティ（関係性）そのものに親子関係を持たせます。
  - **例**: `上司である` `rdfs:subPropertyOf` `一緒に働いている`
- **`rdfs:domain`**（ドメイン / 域）
  - **概要**: そのプロパティの**「主語（主格）」側**が属すべきクラスを指定します。
  - **例**: プロパティ `設置されている` の `rdfs:domain` は `産業機器`
  - **効果**: 「設置されている」の主語となるリソースは、明示されていなくても自動的に「産業機器」のインスタンスであると推論されます。
- **`rdfs:range`**（レンジ / 値域）
  - **概要**: そのプロパティの**「目的語（目的格）」側**が属すべきクラスやデータ型を指定します。
  - **例**: プロパティ `設置されている` の `rdfs:range` は `工場・ライン`
  - **効果**: 「設置されている」の目的語となるリソースは、自動的に「工場・ライン」クラスに属すると推論されます。
