## 1. 全体像：セマンティック（意味論）という大きな傘

- **「セマンティック」**と**「オントロジー」**は並列関係ではなく、**包含・階層の関係**。
- セマンティックは「データに意味や文脈を持たせる」思想・技術全体の総称。

```text
  ┌────────────────────────────────────────────────────────┐
  │              セマンティック (Semantics)                 │
  │  ┌──────────────────────────┐  ┌─────────────────────┐  │
  │  │ 具体的な手段 (緩い→厳密)  │  │ 実装・運用の仕組み  │  │
  │  │ ① グロッサリー            │  │ ● セマンティック層  │  │
  │  │ ② シソーラス              │  │ ● ナレッジグラフ    │  │
  │  │ ③ タクソノミー            │  │ ● データカタログ    │  │
  │  │ ④ オントロジー            │  │                     │  │
  │  └──────────────────────────┘  └─────────────────────┘  │
  └────────────────────────────────────────────────────────┘
```

---

## 2. 知識表現のグラデーション（4段階モデル）

データに意味を持たせるアプローチは、人間向け（緩い）からコンピュータ向け（厳密）へと段階的に進化する。

| レベル | 名称 | 内容 | センサーデータの例 | 理解度 |
| :---: | :--- | :--- | :--- | :---: |
| **①** | **グロッサリー** | 用語の定義や説明を自然言語で記述 | 「`temp1` は機器Aの外側温度センサー値」 | ❌ 文字列 |
| **②** | **シソーラス** | 同義語・類義語・関連語を定義 | 「温度」≒「Temperature」/ 上位:「イベント」 | △ 揺れ吸収 |
| **③** | **タクソノミー** | 概念を親子関係（Is-A）で階層分類 | `計測器 > センサー > 温度センサー` | ○ 階層理解 |
| **④** | **オントロジー** | 多角的な関係性 ＋ 論理 ＋ 推論規則 | 「センサーは機器Aに設置」「X度以上＝異常」 | ◎ 自動推論 |

---

## 2. 各段階の詳細（① グロッサリー & ② シソーラス）

### ① グロッサリー（Glossary / 用語集）
- **特徴**: 用語の定義や説明文を自然言語で記述（人間向け）。
- **実務ツール**: データカタログ（DataHub, Atlan 等）、Confluence、Notion。
- **限界**: コンピュータにとっては単なるテキストで、機械的な処理には使えない。

### ② シソーラス（Thesaurus / 類語辞書）
- **特徴**: 同義語（synonym）や上位語・下位語の対応関係を定義。
- **実務活用**: 検索システムでの表記揺れの吸収、データ統合時の名寄せ。
- **代表例**: MeSH（医学用語）、SKOS（W3C標準）。

---

## 2. 各段階の詳細（③ タクソノミー & ④ オントロジー）

### ③ タクソノミー（Taxonomy / 分類体系）
- **特徴**: 概念を親子関係（Is-A）で整理した分類ツリー（中間的な厳密さ）。
- **実務活用**: マスタデータの階層管理（商品カテゴリ等）、BIのドリルダウン軸。
- **限界**: 階層関係しか表現できない（「AはBに設置されている」等は不可）。

### ④ オントロジー（Ontology / 知識体系）
- **特徴**: 「概念（クラス）」「関係性（プロパティ）」「推論規則」を定義。コンピュータが自動的に論理的な推論を行える。
- **実装技術**: OWL（Web Ontology Language）、RDF/RDFS。
- **実体化の手段**: ナレッジグラフ。

---

## 3. オントロジーとナレッジグラフの関係

### 「設計図（TBox）」と「実体（ABox）」の関係

オントロジーとナレッジグラフは、データベースにおけるスキーマとデータ（レコード）の関係に相当する。

| 概念 | 役割 | DBでの例え | 記述する内容 |
| :--- | :--- | :--- | :--- |
| **オントロジー**<br>(TBox: Terminological) | 知識の枠組み・設計図 | テーブル定義<br>(スキーマ / DDL) | 「人間」「会社」クラスの定義や、「〜に所属する」などの関係性ルール |
| **ナレッジグラフ**<br>(ABox: Assertion) | 知識の実体・具現化 | レコード<br>(データそのもの) | 「田中さん（人間）は、A社（会社）に所属する」という具体的な事実（トリプル） |

---

## 3. ナレッジグラフのデータモデル

グラフデータベースの内部データモデルには、主に以下の2方式がある。

- **RDF（トリプルモデル）**
  - **特徴**: W3C標準。「主語-述語-目的語」で表現。Web規模のデータ連携に強み。
  - **クエリ言語 / 製品**: SPARQL / GraphDB, Stardog, Apache Jena
- **プロパティグラフ（LPG）**
  - **特徴**: ノード・エッジ自体にキー・バリューの属性を持てる。直感的で実務向き。
  - **クエリ言語 / 製品**: Cypher, Gremlin / Neo4j, Amazon Neptune

---

## 3. W3C標準の階層構造（RDF / RDFS / OWL）

オントロジーのルールや定義を記述するためのW3C標準レイヤー。

```text
  +------------------------------------------+
  |              Logic / Rules               |
  +------------------------------------------+
  |                   OWL                    |  ← 推論・制約・高度な論理関係を定義
  +------------------------------------------+
  |                  RDFS                    |  ← 基本的なクラスやプロパティの階層定義
  +------------------------------------------+
  |                   RDF                    |  ← 事実（主語-述語-目的語のトリプル）を記述
  +------------------------------------------+
```

- **RDF**: 事実の記述（「センサーAは工場Xに設置されている」）
- **RDFS**: 基本構造（「温度センサーは計測機器のサブクラス」）
- **OWL**: 推論ルール（「is_part_of は推移的」「Aの逆関係はB」）

## 4. セマンティックレイヤー

### 概念の世界と物理データの仲介者
物理的なテーブル・カラムと、ビジネス概念（メトリクスや結合ルール）を接続する**「実務的な翻訳ミドルウェア」**。

```text
  [ 利用層 ]   BIツール (Looker等) / AIエージェント (Text-to-SQL)
                  ▲
                  │ (ビジネス用語で安全にクエリを投げる)
  ┌───────────────┼────────────────────────────────────────┐
  │ 意味の世界    ▼                                        │
  │  ● オントロジー / ナレッジグラフ (論理・推論の頂点)    │
  │  ● セマンティックレイヤー (メトリクス、結合ルールの定義) │
  │  ● グロッサリー / データカタログ (人間向けの説明)      │
  └───────────────┬────────────────────────────────────────┘
                  │ (裏側で複雑な物理SQLに自動変換)
                  ▼
  [ 物理層 ]   DWH (Snowflake / BigQuery / 各種物理テーブル)
```

---

## 4. セマンティックレイヤーとオントロジーの違い

| 切り口 | セマンティックレイヤー | オントロジー / ナレッジグラフ |
| :--- | :--- | :--- |
| **主な目的** | 指標の計算結果や結合ルール（SQL）がブレないようにする | 複雑な現実世界の概念関係を整理し、論理的な推論をさせる |
| **定義対象** | メトリクス、ディメンション、結合（Join）ルール | クラス（概念）、関係性（プロパティ）、推論規則 |
| **実務の例** | `AVG()` 等の計算式、物理テーブル間のJoin条件 | 「温度センサーが故障 → 計測値の信頼度は低」という知識モデル |

### 💡 AIエージェント時代における価値
AIに生テーブルを直接見せるとSQL結合のミスやハルシネーションが起きる。セマンティックレイヤーを挟むことで、AIはビジネス言語のままで正確なデータを取得可能になる。

---

## 4. 主要なツールと規格

- **dbt Semantic Layer (MetricFlow)**
  - Metrics-as-Code。YAMLで定義し、Gitによるバージョン管理やCI/CDが可能。
- **Cube**
  - ユニバーサルセマンティックレイヤー。REST/GraphQL/SQL APIを提供。
- **LookML (Looker)**
  - Looker独自のデータモデリング言語。草分け的存在。
- **Open Semantic Interchange (OSI)**
  - ツール間でセマンティック定義を持ち運ぶための共通YAML規格。
  - Snowflake, Salesforce, dbt Labs, Cubeなどが提唱。
  - **JSON-LDとの違い**: JSON-LDはWebデータ統合用。OSIはSQL/メトリクス定義用。

---

## 5. データマネジメントの周辺概念

データマネジメント全体の「信頼性」を保証するための不可欠な周辺領域。

- **メタデータ管理**: データの「データ」を一元管理。
  - *テクニカル* (型・制約)、*ビジネス* (意味・オーナー)、*オペレーショナル* (更新ログ)
- **データガバナンス**: 品質・セキュリティ・プライバシー・コンプライアンスの組織的プロセス。
  - データスチュワードの設置、データリネージ、データ品質の監査。
- **マスターデータ管理 (MDM)**: 「唯一の正しい情報源 (SSOT)」を確立・維持。
- **データ契約 (Data Contract)**: 提供者と利用者の間でのスキーマやSLAの合意。
- **Linked Data**: Web上でデータを公開・相互接続する4原則。

---

## 6. テクノロジースタック（4層レイヤーモデル）

データを「意味を持ったネットワーク」として扱うための技術体系。

- **Layer 1: スキーマ・モデリング層（設計図とルール）**
  - タクソノミー、オントロジー、RDF/OWL、プロパティグラフモデル。
- **Layer 2: データ・インスタンス層（実体と保存）**
  - ナレッジグラフ、エンティティ/ノード/エッジ、Neo4j/Neptune等のグラフDB。
- **Layer 3: セマンティック・クエリ層（翻訳とアクセス）**
  - セマンティックレイヤー、Cypher/SPARQL/Gremlin、マルチホップ推論。
- **Layer 4: アプリケーション・活用層（AI連携と価値創出）**
  - GraphRAG、Vector RAG、ナレッジ自動抽出。

---

## 6. Layer 3 と Layer 4 の違い

Layer 3 は「翻訳者」、Layer 4 は「利用者」の役割を担う。

| 項目 | Layer 3：セマンティック・クエリ層 | Layer 4：アプリケーション・活用層 |
| :--- | :--- | :--- |
| **役割** | **翻訳者・仲介役** | **利用者・消費者** |
| **主な機能** | 人間やAIの意図を正確なデータベースクエリに変換する。 | セマンティック層から取得したデータを活用して価値を生み出す。 |
| **具体例** | `find_affected_machine()` API<br>Cypherクエリのラッパー | AIエージェント（問合せ応答）<br>BIダッシュボード |
| **アナロジー** | 照明のスイッチやスマートスピーカーの受付部 | 家の住人、動作するAIロボット |

---

## 7. 実装技術：OWLによる自動推論の真骨頂

OWLは**リーゾナー（推論エンジン）**を通し、記述されていない事実を自動導出できる。

### 1. プロパティの特性
- **転移性** (Transitive): `AisPartOfB` ＋ `BisPartOfC` ➔ `AisPartOfC`
- **対称性** (Symmetric): `A隣接B` ➔ `B隣接A` を自動定義
- **逆関係** (Inverse Of): `A hasPart B` ➔ `B isPartOf A`

### 2. クラスの論理演算
- **排他性** (Disjoint): `Normal` と `Error` に同時に属することはできない。
- **等価性** (Equivalent): 「温度 ≥ 100℃ かつ 圧力異常」➔ 自動的に `DangerState` クラスに分類。

---

## 7. 実装技術：RAG手法の比較

| 比較項目 | Vector RAG（通常のRAG） | GraphRAG（ナレッジグラフ活用） |
| :--- | :--- | :--- |
| **検索の仕組み** | ベクトル空間上の意味的類似度（距離）で検索 | エンティティ関係性の線（エッジ）を辿って検索 |
| **得意な問い** | 「特定の仕様書やドキュメントのピンポイント検索」 | 「システム全体の構成」「要素AとBの間接的な関係性」 |
| **弱点** | 複数ドキュメントを跨ぐ構造的・大局的な問いに弱い | グラフスキーマの設計やデータ構築コストが高い |

- **OSIの位置づけ**: セマンティックレイヤーのロックインを防ぐ共通規格。YAMLを用いて、dbtやCubeなどの定義をポータブルにする。

---

## 8. 現代の AI・LLM 文脈における変化

### トップダウンからボトムアップへ
かつては「まず厳密なオントロジー（OWL/RDF）を設計し、データを流し込む（トップダウン）」が主流だったが、現在は「LLMによって非構造化データからエンティティ・関係性を抽出し、ナレッジグラフを構築する（ボトムアップ）」アプローチが主流に。

### スキーマとしてのオントロジーの重要性
ボトムアップアプローチでも、グラフの品質を保つために「緩やかなスキーマ」が必要。
- **表記揺れ**（同一対象の重複）の防止
- **関係性の不統一**（「所属する」「勤める」の混在）の防止
- **粒度のバラバラ化**（過度な一般化・詳細化）の防止

# まとめ：AIエージェント時代のデータ基盤

現代のAI/LLMシステムにおいて、データに意味を与える技術は必須の構成要素。

1. **セマンティックレイヤー**: AIがハルシネーションなく、安全にSQLを生成するための「辞書」。
2. **ナレッジグラフ & GraphRAG**: AIの外部記憶装置。要素間の関係性を辿る構造的推論のインフラ。
3. **オントロジー**: コンピュータ（AI）がデータの意味と論理規則を正しく理解するための知的フレームワーク。

これらを組み合わせることで、**「データの意味を理解し、正しく推論・集計できるAIエージェント」**の構築が可能になる。
