# データ分析エージェントが作成した分析結果を敵対的にレビューするエージェントが利用するチェックリスト


## 概要

- 分析データや分析手法に応じて、動的に AgentSkills で呼び出して利用するチェックリスト
- データ分析とソフトウェア開発の大きな違いとして、コーディングは「創造性」が求められ、テストコードという防波堤があります。しかし、データ分析には「唯一の正解」しかなく、LLM の創造性が裏目に出ることがあります。

```sh
チェックリスト
├─ [軸A] 共通（全分析に必ず適用）
│   ├─ 論理・推論の妥当性
│   ├─ バイアス
│   ├─ 推測・補完
│   ├─ 統計的誤謬
│   └─ 解釈可能性・説明責任
│
├─ [軸B] 分析フェーズ別（フェーズに応じて選択）
│   ├─ データ収集・サンプリング
│   ├─ データ品質・前処理
│   ├─ 探索的データ分析（EDA）
│   ├─ 機械学習・モデリング
│   ├─ 可視化・レポーティング
│   └─ 本番適用・モニタリング　★新規
│
├─ [軸C] データ種別（対象データに応じて選択）
│   ├─ 時系列データ
│   ├─ クロスセクション・テーブルデータ
│   ├─ テキスト・NLP データ　★新規
│   ├─ 画像データ　★新規（必要なら）
│   └─ 地理空間データ　★新規（必要なら）
│
└─ [軸D] 業種・ドメイン別（業種に応じて選択）
    ├─ 製造業
    ├─ 小売・EC　★新規（必要なら）
    └─ ...
```

## プロセス

1. 分析案の作成（データ分析エージェント）
   - それぞれのデータの理解と用途の整理
   - 分析目的と分析方法の一覧作成
2. 人間による確認（分析案レビュー）
3. 分析の実行（データ分析エージェント）
4. 敵対的レビュー（レビューエージェントが本チェックリストを適用）
5. 成果物の納品（人間の最終確認）


## チェックリストの構成（3軸モデル）

AI Agent は分析内容に応じて以下の軸から必要なモジュールを選択してロードする。

| 軸 | 説明 | 選択タイミング |
|---|---|---|
| **軸A: 共通** | 全ての分析に必ず適用 | 常時ロード |
| **軸B: 分析フェーズ別** | 分析の段階に応じて選択 | フェーズ確認後にロード |
| **軸C: データ種別** | 対象データの種類に応じて選択 | データ定義確認後にロード |
| **軸D: 業種・ドメイン別** | ドメイン固有ルールの確認 | 業種確認後にロード |


## システムプロンプト設計メモ

### データ分析エージェントのシステムプロンプトに含める指示

- [ ] レポートの冒頭に必ず「AI による自動分析であること」と「注意点」を明記させる
- [ ] 使用データの出典（テーブル名・集計期間・フィルタ条件など）を明記させる
- [ ] 欠損値・異常値の処理方法とその根拠を必ず記載させる
- [ ] 補完・推測を行った場合は、その箇所と根拠を明示させる（推測による補完の禁止、または禁止できない場合は明示の義務付け）
- [ ] 結論に至るロジックをステップごとに説明させる
- [ ] 信頼性スコア（分析の確実度）を付与させる
- [ ] 判断できない・データが不足している場合は「不明」と明示させ、推測で埋めることを禁止する

### 敵対的レビューエージェントのシステムプロンプトに含める指示

- [ ] 分析結果の「正しさ」ではなく「誤りの可能性」を探すことを最優先タスクとして設定する
- [ ] 本チェックリストを分析手法・データ種別に応じて動的に選択し適用させる
- [ ] 各チェック項目に対して「問題なし / 要確認 / 問題あり」の三段階で判定させる
- [ ] 「問題あり」「要確認」の場合は、該当箇所の引用と具体的な懸念点を記載させる
- [ ] レビュー結果の冒頭に総合リスクスコア（例：低 / 中 / 高）を付与させる
- [ ] 自信がない項目については、推測で「問題なし」と判定せず「確認不能」と返答させる

# 軸A: 共通チェック項目（全分析に適用）

## A-1. 論理・推論の妥当性

- [ ] 論理の飛躍: 分析結果から結論までのロジックに、データで裏付けられていない飛躍はないか？
- [ ] 因果の断定: A/B テストなどの介入を行っていない観察データにもかかわらず、「〜すれば〜になる」という因果関係を断定していないか？
- [ ] 実用性の欠如: 統計的に有意であっても、ビジネス上のアクションに繋がらない（コントロール不可能な変数に依存している）結論になっていないか？

## A-2. バイアスの確認

- [ ] サバイバーシップ・バイアス: 成功したデータ（現在稼働している機械、退会していない顧客など）のみで分析し、失敗したデータが欠落していないか？
- [ ] 選択バイアス: サンプリングされたデータが、母集団全体を正しく代表しているか？
- [ ] チェリーピッキング（期間・KPI の恣意的選択）: 都合のよい期間・サブグループ・指標のみを選び、全体像を歪めていないか？（例：業績が良かった四半期だけを切り出して成長を語っていないか）

## A-3. 推測・補完の確認

- [ ] 欠損値の補完根拠: 欠損値をゼロ・平均・前後の値で補完している場合、その根拠が明示されているか？
- [ ] 不足データの推測禁止: データが存在しない箇所を、根拠なく推測・補完していないか？

## A-4. 統計的誤謬

- [ ] 因果と相関の混同: 2 つの変数が相関しているだけで、片方がもう片方の原因であると断定していないか？
- [ ] 擬似相関・交絡因子: 無関係な 2 つの変数が、第 3 の変数（交絡因子）によって相関しているように見えていないか？
- [ ] 平均値の罠: 分布が極端に歪んでいる（一部の異常値が引き上げている）のに、中央値ではなく平均値で全体を語っていないか？
- [ ] 分母・基準値の操作: 増加率・達成率などの計算で、分母や基準期間を恣意的に変更して数字を大きく（または小さく）見せていないか？（例：前月比ではなく前々月比に切り替えて改善を誇張）
- [ ] p-hacking / 多重比較: 多数の仮説検定を繰り返し、有意になったものだけを報告していないか？多重比較補正（Bonferroni 法など）は適用されているか？

## A-5. 解釈可能性・説明責任

- [ ] ステークホルダーへの説明可能性: 分析結果と結論が、技術的な知識を持たないステークホルダーにも正確に説明できる言葉で書かれているか？
- [ ] 判断不能箇所の明示: データ不足や不確実性が高い箇所が「不明」「要確認」として明示されているか？推測で埋められていないか？

# 軸B: 分析フェーズ別チェック項目

## B-1. データ収集・サンプリング

- [ ] 収集期間の代表性: サンプリング期間が、分析目的に対して適切な長さ・タイミングを網羅しているか？
- [ ] 収集方法の偏り: データの収集方法（ログ、アンケート、センサーなど）に起因する系統的な偏りがないか？
- [ ] 欠測データの発生メカニズム: 欠損がランダムに発生しているか（MCAR/MAR）、それとも欠損自体に意味があるか（MNAR）を確認しているか？

## B-2. データ品質・前処理

- [ ] 名寄せ: 同一エンティティの表記ゆれ（例：「株式会社〇〇」と「(株)〇〇」）が未処理のまま集計されていないか？
- [ ] 単位変換ミス: 単位（例：kg vs lb、円 vs 千円、℃ vs K）の変換が正しく行われているか？
- [ ] 重複レコードの未除去: 同一の取引・観測が重複して存在し、件数・金額・平均値が過大計上されていないか？（特にデータ結合後の重複に注意）
- [ ] 結合（JOIN）キーの誤り: テーブル結合のキー設定が誤り、意図せず 1:N が N:N になり行数が膨張していないか？
- [ ] 日付・タイムゾーンのミス: 日付のパース形式やタイムゾーンの混在（UTC と JST など）により、期間集計がずれていないか？
- [ ] 集計粒度の不一致: 日次・週次・月次など、異なる粒度のデータを混在させて集計していないか？
- [ ] 前提の妥当性: 欠損値の処理・異常値の除外基準は、ドメイン知識に照らして妥当か？

## B-3. 探索的データ分析（EDA）

- [ ] 分布の確認��漏れ: 各変数の分布（ヒストグラム・箱ひげ図）を確認せずに平均・相関だけで判断していないか？
- [ ] 外れ値の未確認: 外れ値の存在を確認せずに集計・モデリングに進んでいないか？
- [ ] 多重共線性（マルチコ）の未確認: 互いに強い相関のある特徴量を同時にモデルに投入し、係数や重要度が不安定になっていないか？
- [ ] カテゴリ変数の分布確認漏れ: カテゴリ変数のクラス分布（件数・割合）を確認せずにモデルに使用していないか？

## B-4. 機械学習・モデリング

- [ ] 未来情報の漏洩（データリーク / Look-ahead Bias）: 予測時点では得られないはずの未来のデータを、予測モデルの特徴量に含めていないか？
- [ ] 過学習（Overfitting）: 特定の期間や訓練データにのみ適合しすぎた結果を出力していないか？
- [ ] 評価指標の不一致: ビジネスの目的に合致しない評価指標（例：見逃しが許されないケースなのに Recall ではなく Precision を優先）を使っていないか？
- [ ] クラス不均衡の無視: 異常検知や離反予測などで、圧倒的少数派のクラスを予測する際に、正解率（Accuracy）だけでモデルを評価していないか？（Precision / Recall / F1 も確認しているか）
- [ ] 特徴量重要度の矛盾: SHAP 値や変数の係数が、既知の物理法則やビジネスルールと逆行していないか？（逆行している場合、多重共線性や交絡の疑いがある）
- [ ] 再現性の欠如: 乱数シードが固定されておらず、再実行で結果が変わる可能性がないか？
- [ ] 解釈可能性: モデルの判断根拠が示されておらず、ブラックボックスのまま結論が出されていないか？

## B-5. 可視化・レポーティング

- [ ] Y 軸のゼロ起点: Y 軸がゼロ起点でなく、わずかな変化量を誇張して見せていないか？
- [ ] カテゴリの並び順: カテゴリの並び順が恣意的で、特定の傾向を強調・隠蔽していないか？
- [ ] 積み上げグラフの混同: 積み上げグラフで、総量の変化と比率の変化を混同していないか？
- [ ] 軸ラベル・単位の欠如: 軸のラベルや単位が欠落しており、読み手が誤解する可能性がないか？
- [ ] サンプル数の非表示: グラフにサンプル数（n 数）が表示されておらず、少数データの傾向を過大評価していないか？

## B-6. 本番適用・モニタリング

- [ ] モデルドリフトの考慮: 本番環境で時間の経過とともにデータ分布が変化（コンセプトドリフト・データドリフト）した場合の検知・再学習の仕組みが考慮されているか？
- [ ] 訓練データと本番データの乖離: 訓練時と本番適用時でデータの取得条件・定義が異なっていないか？
- [ ] 閾値設定の根拠: 分類モデルの閾値（例：異常判定の境界値）がビジネス要件に基づいて設定されているか？感度分析は行われているか？
- [ ] フィードバックループの考慮: モデルの出力が次期のデータ収集に影響を与えるフィードバックループが生じていないか？

# 軸C: データ種別チェック項目

## C-1. 時系列データ

- [ ] 少量データでのトレンド断定: 少量のデータポイントのみで、長期的なトレンドを断言していないか？
- [ ] 自己相関の無視: 時間的な連続性（過去の値が現在の値に影響する性質）を無視して、独立したデータポイントとして扱っていないか？
- [ ] 季節性・トレンドの未処理: 曜日変動・季節変動・長期トレンドを分離・考慮せずに、突発的な異常だと誤認していないか？
- [ ] 未来予測のリーク: シフト処理（ラグ特徴量の作成）を誤り、未来の値を予測に使っていないか？

## C-2. クロスセクション・テーブルデータ

- [ ] 外れ値の過大評価: 極端な外れ値が平均値や回帰直線を大きく歪めているのに、それを取り除かずに結論を出していないか？
- [ ] 集計の Simpson のパラドックス: 全体の集計では見えていた傾向が、グループ別に分解すると逆転していないか（グループ間の構成比の違いによる見かけ上の逆転）？

## C-3. テキスト・NLP データ

- [ ] 前処理の一貫性: トークナイズ・正規化（大文字小文字、記号除去など）の処理が学習時と推論時で一致しているか？
- [ ] ストップワード・語彙の妥当性: ドメイン固有の重要語がストップワードとして除去されていないか？
- [ ] 感情分析の文脈依存: 否定表現（「良くない」）や文脈依存の言葉が正しく処理されているか？
- [ ] ラベルの曖昧さ: アノテーションに主観的・曖昧な判断が含まれていないか？クラス間の定義は明確か？
- [ ] データの時間的偏り: テキストデータが特定の期間・話題に偏っており、汎化性能が低下していないか？

# 軸D: 業種・ドメイン別チェック項目

## D-1. 製造業（共通）

- [ ] 工学値の変換ミス: 工学値はスペックシートに基づいて正しく変換されているか？（スペックシートが与えられない場合、推測で変換していないか？）
- [ ] センサードリフト・校正の考慮: センサーの経年劣化やキャリブレーションのズレを考慮しているか？
- [ ] 停止期間の区別: 生産ラインの停止期間が「計画停止（メンテナンス）」と「故障停止」で区別されているか？混在したまま稼働率を計算していないか？
- [ ] 階層構造の無視: バッチ ID・設備 ID・ライン ID などの階層構造を無視した集計（例：設備間の差異を無視した平均化）になっていないか？

## D-2. 製造業（水処理）

- [ ] 水質基準値との整合: 分析結果が水質基準（例：水道法・排水基準）と照合されているか？
- [ ] 流量・水位の変動要因の考慮: 季節的な流入量変動（梅雨・雪解け）や急激な天候変化が外れ値として誤検知されていないか？
- [ ] 薬品注入量との連動確認: 水質変化を分析する際に、薬品注入量の変化が交絡因子として考慮されているか？
- [ ] 検出限界以下データの扱い: 検査値が検出限界（ND）以下の場合の処理方法（0 扱い、1/2 法など）が根拠とともに明示されているか？
- [ ] 設備の系列・ブロック構成の考慮: 複数系列（A 系・B 系）や複数池（沈澱池・ろ過池）の独立性を無視した集計になっていないか？

## D-3. マーケティング

- [ ] アトリビューション: コンバージョン貢献をラストクリックのみで評価し、上位ファネルの貢献（認知・検討段階）を無視していないか？
- [ ] 広告効果の因果検証: 広告費増加と売上増加の相関を因果として断定していないか？（外部要因・季節性の影響を排除しているか）
- [ ] カスタマージャーニーの分断: オンライン・オフラインのタッチポイントを統合せずに部分的なデータのみで評価していないか？
- [ ] コホートの定義の一貫性: 顧客コホートの定義（初回購買日、登録日など）が分析間で統一されているか？
- [ ] LTV 計算の前提確認: 顧客生涯価値（LTV）の算出に用いる継続率・単価の前提が、現在のデータに即しているか？
