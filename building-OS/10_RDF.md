# RDF（Resource Description Framework）

## RDFの概要

**RDF（Resource Description Framework：リソース記述フレームワーク）**は、ウェブ上にある「モノ」や「コト」の情報を、コンピュータが解釈・処理しやすい形で表現するための世界標準（W3C勧告）のデータモデルです。

主に、データを網の目のようにつなぐ「ナレッジグラフ（Knowledge Graph）」や「セマンティックウェブ」の基盤技術として広く活用されています。


## RDFの特徴

### 1. 最大の特徴：「トリプル」による表現

RDFでは、どんなに複雑な情報であっても、すべて**「主語（Subject）」「述語（Predicate）」「目的語（Object）」**という3つの要素の組み合わせ（これを**トリプル**と呼びます）に分解して表現します。

上記のシステム概念図（例）をトリプルに分解すると、次のような構造になります。

- **主語 (Subject)**: 記述の対象となるリソース（例：人物ノード `Bess Schrader`）
- **述語 (Predicate)**: 主語と目的語の関係性や属性（例：`employed by` / 〜に雇用されている）
- **目的語 (Object)**: 関係の宛先や具体的な値（例：組織ノード `Enterprise Knowledge`）

このトリプルを大量に積み重ねていくことで、データ同士が数珠つなぎになり、巨大な**グラフ構造（ネットワーク状のデータ）**が形成されます。

### 2. グローバルで衝突しない「URI」の利用

RDFでは、主語や述語に**URI（Uniform Resource Identifier）**というWebのURLに似た識別子を割り当てます。

これにより、世界中の異なるシステムが作成したデータであっても、名前の衝突（同姓同名の混同など）を起こさずに、データを安全に結合・リンクさせることができます。

### 3. 主要な記述形式（シリアライズ）

RDFモデルを実際にファイルに書き出したり、プログラム間でやり取りしたりするための構文（フォーマット）には、いくつかの種類があります。

| 形式名 | 特徴 | 主なユースケース |
| :--- | :--- | :--- |
| **Turtle** (タートル) | 人間にとって最も読みやすく、書きやすいシンプルなテキスト形式。 | ナレッジグラフの手動記述や設計・学習時 |
| **JSON-LD** | Webで標準的なJSONをベースに、RDFの概念を拡張した形式。 | Webサイトの構造化データ（SEO対策・Googleの検索エンジン最適化） |
| **RDF/XML** | XMLベースの初期からある形式。機械処理には向くが人間には冗長。 | レガシーなシステムや一部の標準化データとの連携 |



## RDFがもたらすメリット

- **柔軟なデータ統合**
  - 関係型データベース（RDB）のように、事前にガチガチのテーブル設計（スキーマ）を決めなくても、後から新しいトリプル（関係性）を自由に追加・結合できます。
- **機械による「推論」の実現**
  - 「AはBの親」「BはCの親」というデータがあれば、システムが自動的に「AはCの祖父母である」と判断するような、論理的なデータ補完（推論）が容易になります。
